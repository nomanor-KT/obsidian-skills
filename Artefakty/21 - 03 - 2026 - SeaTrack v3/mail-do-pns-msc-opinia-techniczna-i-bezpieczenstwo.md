Temat: Prośba o ocenę bezpieczeństwa - SeaTrack + API armatorów (tracking)

Cześć Michał,

Potrzebuję od PNS krótkiej oceny bezpieczeństwa dla integracji SeaTrack z API armatorów.

Kluczowy kontekst:
- Każda integracja API z armatorem dotyczy wyłącznie trackingu kontenerów.
- Do armatora wysyłamy tylko numer kontenera albo numer BL (identyfikator przesyłki).
- Z armatora odbieramy tylko dane trackingowe (ETA/ETD, ewentualnie nazwa statku).
- Nie wysyłamy pełnej bazy klientów ani innych szerokich danych operacyjnych.

Rola SeaTrack:
- SeaTrack jest nakładką wizualizacyjną (Kanban bieżących transportów).
- Nie zastępuje obecnego TMS i nie zmienia kluczowych procesów operacyjnych.
- Jeśli SeaTrack nie działa, firma nadal działa na obecnych rozwiązaniach.

Zarząd i Prawny potrzebują od Was potwierdzenia, że przy takim zakresie możemy iść dalej bez ryzyk „niewidocznych na starcie”.

Proszę o odpowiedź w prostym układzie:

1) Ocena bezpieczeństwa (TAK / WARUNKOWO / NIE)
- Czy przy tym zakresie danych rozwiązanie można bezpiecznie uruchomić?

2) Braki przed uruchomieniem
- Co jest obowiązkowe do zrobienia przed startem (krótka lista must have)?

3) Nadzór po uruchomieniu
- Jak powinien wyglądać minimalny nadzór IT/PNS nad aplikacją po starcie?
- Kto powinien być właścicielem tego nadzoru po stronie firmy?

4) Ryzyka praktyczne
- Jakie realne ryzyka widzicie przy takim modelu (tracking-only)?
- Co rekomendujecie dodać, żeby te ryzyka ograniczyć?

5) Szacunek
- Jaki orientacyjny czas i nakład pracy są potrzebne, żeby domknąć wymagania?

Jeżeli wygodniej, zróbmy 30-min call i przejdziemy przez to punkt po punkcie.
